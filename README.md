# 财务台账清洗系统

把一个"脏"的财务台账 CSV 清洗成可直接分析的干净数据，并**量化证明清洗有效**。

> 关键不是"跑通了六步"，而是：**知道埋了多少坑、抓回多少、漏了多少。**

---

## 一条命令跑完

```bash
py generate_dirty_data.py    # 造 1990 行脏数据 + 标准答案
py clean.py                  # 清洗 + 生成报告
py -m pytest test_clean.py   # 41 项测试
```

产物：

```
data/raw_台账.csv            1990 行脏数据
data/cleaned_台账.csv        1846 行干净数据
data/issues_异常清单.csv      74 条待人工复核（带级别和建议）
data/truth_埋坑清单.json      生成器留下的标准答案
report.html                 可视化报告
```

## 六步流水线

| 步骤 | 做什么 | 关键点 |
|---|---|---|
| 1 日期标准化 | 5 种格式统一成 `%Y-%m-%d` | 先试固定格式，猜不出来才算失败 |
| 2 金额清洗 | 去 `¥ / 元 / 千分位 / 空格` | 会计括号 `(1,234.56)` = 负数 |
| 3 科目标准化 | 25+ 种写法归并成 8 个标准科目 | 靠映射表，这是业务知识 |
| 4 去重 | **用标准化后的值**做业务键 | 见下面的坑 2 |
| 5 缺失值 | 摘要补「（未填写）」，其余转人工 | **不瞎猜** |
| 6 校验 | 7 条规则表，分错误/警告/提示 | R001~R007 |

## 三个核心设计

### 1. 缺失值不瞎猜

财务数据填错一个数，比空着危害大得多。所以：

- 日期 / 金额 / 科目缺任何一项 → **不进干净数据**，全部进异常清单
- 异常清单带**级别**（错误 / 警告 / 提示）和**建议处理**

宁可少给 1846 行，也不交半成品。

### 2. 去重要在标准化之后

同一笔业务可能被录成：

```
2024/1/5    销售费     ¥1,234.56
2024-01-05  销售费用   (1,234.56)
```

字面完全不同，其实是同一笔。用原始列去重抓不到，必须先标准化再比。

### 3. 清洗效果可量化

生成器埋坑时**同步写下标准答案**（`truth_埋坑清单.json`），清洗后逐项核对：

```
✅ 去重      应有 100 / 抓到 100 / 漏 0   (100%)
✅ 日期缺失   应有  14 / 抓到  14 / 漏 0   (100%)
✅ 金额缺失   应有  11 / 抓到  11 / 漏 0   (100%)
✅ 科目缺失   应有  19 / 抓到  19 / 漏 0   (100%)
✅ 金额离谱   应有  30 / 抓到  30 / 漏 0   (100%)
```

这不是"我觉得洗干净了"，是**对照答案验过的**。

## 数据质量评分（6 维度）

| 维度 | 含义 | 清洗前 | 清洗后 |
|---|---|---|---|
| 完整性 | 关键字段非空率 | 99.4 | **100.0** |
| 唯一性 | 1 − 重复行占比 | 97.0 | **100.0** |
| 有效性 | 日期/金额可解析率 | 99.4 | **100.0** |
| 一致性 | 科目写法归并率 | 22.9 | **100.0** |
| 准确性 | 金额/日期落在合理区间 | 98.6 | **99.2** |
| 规范性 | 日期格式统一程度 | 40.0 | **100.0** |
| **总分** | 六维平均 | **76.2** | **99.9** |

准确性停在 99.2 是**故意的**：30 行金额离谱的记录数据本身完整，只是需要业务确认，
所以留在干净数据里、同时进异常清单，不擅自改数。

## 踩过的四个坑（面试就讲这个）

### 坑 1：正数被套上括号，金额直接变负

生成器给金额随机选写法时，**正数也可能随机到 `paren_neg` 样式**：

```
2024-08-12   管理费    (50,832.11)   → 解析成 -50832.11
20240812     管理费    ¥50832.11     → 解析成 +50832.11
```

同一笔业务，两种写法金额符号相反。后果是去重时被判成两条不同业务，白丢一行。

**修**：括号样式只在负数时用。并加了一条回归测试跑 500 次。

### 坑 2：去重用了原始列，同义重复抓不到

v1 的去重键是 `["凭证号", "日期", "科目", "摘要", "金额"]` —— 全是**原始列**。
同一笔业务换种写法录制，就成两条。

之所以 v1 测试没暴露，是因为造数据时"完全复制"的重复字面一模一样，**碰巧能抓到**。
直到加了"同义重复"（改写法不改变质），才漏出 8 条。

**修**：去重键改用 `日期_标准 / 科目_标准 / 金额_数值`，并且**缺失行不参与去重**
（日期或金额为空时没法判断是不是同一笔，强行去重会误删真实业务）。

### 坑 3：质量分算错对象，清洗后反而变低

一开始"清洗后"的分数是对**中间 df** 算的，那份数据里还留着 44 行缺失记录，
结果完整性、有效性反而比清洗前低 0.1 —— 报告上看着像"越洗越脏"。

**修**：对**最终输出的干净数据**算分。

### 坑 4：一致性公式在小样本上封顶

原公式 `标准科目数 / 实际写法数 * 100`，测试用的 3 行数据只有 3 种写法，
`8/3 = 266` 被封顶成 100，把"三种写法"判成了满分。

**修**：改成归并率 `标准化后种类 / 原始种类`，永远 ≤ 100。

## 测试

41 项，覆盖：

- `parse_date`：5 种格式、空值、非法值
- `parse_amount`：6 种写法、括号负数、全角括号（明确返回 None 不瞎猜）
- `dirty_amount` 往返：**正数不变负**（坑 1 的回归）、负数保持负
- `normalize_subject`：映射、未知科目原样保留
- `assess_quality`：脏数据分数更低、空 DataFrame 不崩
- 标准答案自洽性

```bash
py -m pytest test_clean.py -v
```
